voltage_parser — extraction & normalization rules (input ranges in VDC separate from power consumption in W, VAC, battery, PoE)

Goal / canonical output

input_voltage: normalized string for DC/AC ranges, preferably min–max VDC or min–max VAC

battery_spec: if battery present (chemistry, voltage)

poe: boolean + spec if present (802.3af/at/bt)

notes: raw string for ambiguous cases

1. Label detection

Match aliases: Input voltage, Voltage, Power supply, Supply voltage, Voltage range, VDC, VAC, Battery.

Prefer POWER, ELECTRICAL, SPECIFICATIONS.

2. Candidate selection

Search same line right, next 1–3 lines below, and nearest right-hand column; also scan header rows of spec tables.

3. Tokenization rules

Numeric token regex: \d+(?:[.,]\d+)? and range separators -, –, to, ~.

Units tokens: V, VDC, DCV, Vdc, VAC, VAC~, VAC (50/60 Hz), V AC.

Current tokens that may accompany voltage: A, mA. Keep separate (power_parser handles W).

Recognize PoE, Power over Ethernet, 802.3af, 802.3at, 802.3bt.

Handle phrases like 9–32 VDC, 5–36 V, 100–240 VAC, 12 V nominal, 10–30 V.

4. Unit recognition & canonical units

Separate DC vs AC. Canonical field input_voltage should state unit explicitly: VDC or VAC.

If unit missing and context mentions V, assume DC for receiver devices unless VAC or mains ranges present (>60 V) or VAC keyword exists.

5. Parsing & normalization logic

Range forms:

min - max V or min to max V → normalize separators to en-dash or – and append unit: 9–32 VDC. Detect unit position (per-token or at end) and normalize.

Single value:

12 V → 12 VDC (if context suggests DC) or 12 VAC if VAC present; otherwise record value and set notes: unit ambiguous.

Mains ranges:

100–240 VAC → canonical 100–240 VAC (50/60 Hz) if frequency indicated; else preserve VAC.

Multiple voltage specs:

If both VDC and VAC listed, list both separated by ;.

Battery:

Capture Battery tokens (e.g., Li-ion 3.7 V) into battery_spec (chemistry + voltage + capacity if present).

PoE:

If PoE present set poe: true, capture spec 802.3af/at/bt if indicated.

Nominal voltages:

For 12 V nominal, record input_voltage: 12 VDC (nominal).

6. Ambiguity resolution

If numeric range present without unit and other specs show VDC elsewhere in document, assume same unit. If other specs show VAC or mains frequencies present, assume VAC.

If two ranges separated by or (e.g., 9–36 VDC or 110–240 VAC), keep both as input_voltage: 9–36 VDC; 110–240 VAC and mark as dual-power capable.

7. Confidence scoring

High: explicit unit and label adjacent.

Medium: unit absent but typical device voltage range present and context implies DC.

Low: numeric alone with ambiguous unit and no contextual clues.

8. Fallback & logging

If no explicit voltage tokens near label, search POWER and ELECTRICAL sections for V, VDC, VAC. Log raw candidates and confidence.

For multi-value conflicts log all candidates in _parser_log and place raw excerpt in notes.

9. Normalized output format

input_voltage: "9–32 VDC"

input_voltage: "100–240 VAC (50/60 Hz)"

battery_spec: "Li-ion 3.7 V, 2000 mAh"

poe: "802.3at" or poe: true and poe_spec: "802.3af"

10. Examples

Input voltage: 9–32 VDC → 9–32 VDC (high)

Power supply: 100–240 VAC, 50/60 Hz → 100–240 VAC (50/60 Hz) (high)

Input: 5–36 with other lines showing V elsewhere → 5–36 VDC; confidence: medium

PoE (802.3at) → poe: 802.3at (high)
