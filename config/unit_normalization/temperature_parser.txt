temperature_parser — extraction & normalization rules (operating vs storage, °C / °F)

Goal / canonical output

operating_temperature: {min}°C to {max}°C (or single ±X°C form)

storage_temperature: {min}°C to {max}°C

notes: raw text if ambiguous

1. Label detection

Match aliases: Operating temperature, Operating temp, Temperature range, Storage temperature, Storage temp, Ambient temperature, Temp. range, Environmental temperature.

Prefer blocks ENVIRONMENTAL, PHYSICAL & ENVIRONMENTAL, OPERATING CONDITIONS.

2. Candidate selection

Search same line right, next 1–3 lines below, then nearest right-hand column within layout cluster.

Also scan nearby table cells in the same row or column.

3. Tokenization rules

Recognize numeric tokens with optional sign and decimal: [-+]?\d+(?:[.,]\d+)?.

Recognize unit tokens: °C, C, degC, °F, F, ° C, Celsius, Fahrenheit.

Recognize range separators: -, –, —, to, ~, /, ±.

Normalize decimal commas to dots.

4. Unit recognition & canonical units

Canonical unit: °C.

Accept °F and convert to °C using C = (F - 32) × 5/9. Preserve original in notes if conversion done.

5. Parsing & normalization logic

Prefer explicit labeled values for Operating and Storage. If both present parse both.

Range forms:

min - max unit → parse both and normalize to °C.

±X°C or X°C ±Y°C → interpret as min = X - Y, max = X + Y.

Single value X°C with label Operating temp: X°C → treat as min = max = X°C or output X°C with note.

If units differ within pair (e.g., -40 °F to 70 °C) convert both to °C; prefer explicit unit nearest token.

If tokens contain words ambient, storage, map appropriately.

6. Ambiguity resolution

If a generic Temperature range exists without explicit Operating/Storage context, put value in operating_temperature and set notes: source ambiguous.

If both Ambient and Operating present, prefer explicit Operating for operating_temperature; map Ambient to notes if necessary.

7. Confidence scoring

High (≥90): explicit label Operating/Storage with unit present and clear numeric pair.

Medium (70–89): range present but unit inferred (e.g., -40 to 85 without °C/°F but in environmental block).

Low (<70): single numeric without unit; apply heuristics (assume °C if within typical device ranges) and flag.

8. Fallback & logging

If no temperature label detected, search ENVIRONMENTAL and PHYSICAL blocks for any temperature tokens. Log candidate and set low confidence.

Add captured raw string, page, method to _parser_log. For conversions from °F add original value to notes.

9. Normalized output format

operating_temperature: "-40 °C to 85 °C"

storage_temperature: "-40 °C to 85 °C"

Use °C, space between number and unit, en-dash or to consistently (choose one per project; recommend to in JSON/text).

10. Examples

Operating temperature: -40 °C to +85 °C → operating_temperature: -40 °C to 85 °C (high)

Storage temp: -40°F to 185°F → convert → storage_temperature: -40 °C to 85 °C; notes: original -40°F to 185°F (high)

Temperature range: -40 to 85 (no unit) → operating_temperature: -40 °C to 85 °C; confidence: medium; notes: unit assumed °C
