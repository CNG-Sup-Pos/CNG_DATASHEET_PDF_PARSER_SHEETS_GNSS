latency_parser — extraction & normalization rules (ms, s, μs)

Goal / canonical output

latency: normalized string in milliseconds (ms). Accept single value or range.

notes: raw string when ambiguous.

1. Label detection

Match aliases: Latency, Output latency, Data latency, Processing latency, Position latency, RTK latency, Telemetry latency.

Prefer PERFORMANCE, SYSTEM, TIMING sections.

2. Candidate selection

Same-line right, next 1–2 lines below, then right-hand column clusters. Also accept values in Performance tables.

3. Tokenization rules

Numeric tokens: \d+(?:[.,]\d+)?.

Units: ms, msec, milliseconds, s, sec, seconds, μs, us, microseconds.

Operators / ranges: <, >, -, –, to.

4. Unit recognition & canonical units

Canonical unit: ms. Convert:

s → multiply by 1000.

μs / us → divide by 1000 (or present as fractional ms with appropriate precision).

Preserve inequality signs (<, ≤) in final string (e.g., <1 ms).

5. Parsing & normalization logic

If explicit ms token present, parse numeric and output as integer or 1 decimal if required.

If s present, convert: 0.05 s → 50 ms.

If μs present, convert to ms with 1–3 decimal places depending on magnitude: 500 μs → 0.5 ms.

Range parsing: min–max unit convert both endpoints to ms.

Inequality handling: <20 ms → keep as <20 ms. Convert if unit different.

6. Ambiguity resolution

If multiple latency figures exist (e.g., per-interface latencies), prefer the one explicitly labeled output latency or position latency depending on schema; record others in notes.

If a number without unit is near latency but value seems large (>1000) treat as ms if typical; else flag for manual review.

7. Confidence scoring

High: explicit unit ms, adjacency to latency label.

Medium: unit s or μs and conversion required but context clear.

Low: numeric without unit or conflicting latency numbers.

8. Fallback & logging

If no latency label found, search performance tables for latency or ms clusters. Log candidate strings and page context.

Keep raw text entry in _parser_log with parsing decision and confidence.

9. Normalized output format

latency: "<1 ms"

latency: "50 ms"

latency: "0.500 ms" (for high precision when converting μs)

10. Examples

Output latency: <1 ms → latency: <1 ms (high)

RTK latency 0.05 s → convert → latency: 50 ms (high)

Telemetry latency 500 μs → latency: 0.5 ms (high)

Latency: 20 (no unit) → latency: 20 ms; confidence: medium; notes: unit assumed ms
