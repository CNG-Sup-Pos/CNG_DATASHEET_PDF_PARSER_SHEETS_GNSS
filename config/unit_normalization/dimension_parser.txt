dimension_parser — extraction & normalization rules

Label detection

Search document for labels matching aliases for Dimensions (fuzzy match).

If found, mark line(s) and bounding boxes as candidate label area.

Candidate value selection

Within the same row to the right or within max_label_distance_px, extract contiguous numeric tokens and adjacent unit tokens.

If none found, check the next max_line_gap lines below label.

If still none, scan the entire page for numeric groups with separators likely to be dimensions.

Tokenization

Split candidate text by known separators set: ['x','×','*','·','⋅',' ', 'x ', ' X '].

Recognize separators with optional spaces and optional unit suffixes on each token.

Numeric parsing

For each token extract numeric part using [\d]+(?:[.,]\d+)?.

Normalize decimal commas to decimal points.

Extract unit token (mm, cm, m) if present on token or after group.

Unit normalization

If any token includes explicit unit, convert all tokens to that unit using unit factors.

If tokens have mixed units, convert each to mm then format.

If no units present:

Use unit_priority_order default (mm preferred).

Heuristics: values > 10 likely mm or mm? (conservative: assume mm for typical device dimensions).

Convert final numeric values to mm and round sensibly (1 decimal if fraction present).

Length grouping

If 3 numeric tokens found -> assign L,W,H.

If 2 tokens -> assign LxW; H left blank or inferred if other data exists.

If >3 tokens -> group the first three; log alternates.

Output format

{L} x {W} x {H} mm (omit H if not present)

Always use lowercase 'mm' and spaces x between components.

Example conversions:

235*146*14.5 (mm) -> 235 x 146 x 14.5 mm

235x146x14.5 -> 235 x 146 x 14.5 mm (assume mm unless configured)

Confidence scoring

High confidence if explicit unit present and exactly 3 tokens.

Medium if explicit unit and 2 tokens.

Low if no units or tokens split across lines.

Fallback & logging

If ambiguous, place raw captured string into Notes and log to _parser_log.
